# makeDocs：Agent 制作规则

## 任务边界与交付

- 案例目录、文档角色和叙事标准统一按`案例叙事标准.md`、`case_structure.json`执行，不再为每朝另造平铺结构。主干文档同名同位置，原稿附录可保留；只许用实际材料填充，不为目录一致虚构内容。
- 对外成果执行`研究成果发布规范.md`。背景综述交代形成、运行、群体与地域差异，本朝专题用本期材料检验变化；不能只写“沿袭前朝，仍待考证”。制度争议须明确影响何项结论，已能成立的解释必须实质展开。
- `研究维度覆盖.md`逐项记录证据和缺口。宦官、神策军、枢密、外镇监军须分别研究，不以人物名出现或目录存在表示该维度完成。新增材料同时更新编年、人物、空间关联和出处记录。

- 整理成果写入 `docs/cases/<case-id>/`；工具、模板与规范留在 `makeDocs/`，程序说明留在 `reader/`。不要以复制整个项目代替整理。
- 本版本案例按宣宗模板配置20篇共同主干及“文化制度以及影响研究”11专题，具体同名路径见`case_structure.json`；登记`docs/cases.json`的结构版本、文档分组及旧路径映射。各朝素材量不必相等，不以空文件、前朝内容复制或关键词列表冒充完成。
- 案例入口说明范围、年限、研究问题、当前核验状态，并链接各分册。分期、纪年导航必须指向现有文档，不能产生空入口。
- 同一事件采用稳定编号；人物、地名、制度变化互相引用。材料不足时标待考，不能靠推测补足。

## 资料查证流程

1. 先检索当前 `docs/` 以避免重复。阅读 `reader/sources.json` 的已登记出处；不随意猜测 ID。新卷章需在阅读器登记并验证后再引用。
2. 优先使用独立原文库：`python makeDocs/query_text.py --book-id B01-137 --query 短语`，再根据命中章ID执行`python makeDocs/query_text.py --chapter B01-137:20`读取上下文。保留实际书目/章ID、段号、source_sha256、decoder、核验状态与查询日期。版本尚未结构化的字段仍需查原库版本资料，不能猜测。
3. 独立库不可用或需检查原始字形版式时，`python makeDocs/query_source.py J18 --query 短语 --open` 会真实打开汉籍窗口并等待结果；不加--open只解析目录。使用前确认桌面可供操作，复用既有驱动：选书方框勾选→打开→最大化→双击卷章→查询。不要另写固定坐标自动化，不要把目录头当作正文。
4. Agent 须实际读取命中的上下文；按需留存截图或逐段核对笔记。`state=done` 只表示驱动任务结束，`textVerified=false` 仍须尊重。未读取原文则写“目录已核／正文待核”。
5. 引文记录书名、卷次、篇章、纪年与条目、版本、本机检索词、核对日期、核对范围及证据位置。原文与现代译述、作者推断分开。
6. 对照《旧唐书》《新唐书》《资治通鉴》及地理志；它们不是独立一致的证据，须记录同源、异文、年月矛盾。制度通论与前后时代材料只作背景，不能直接替代本期史实。

## 研究视角

按问题选择相关维度，不为凑栏目虚构内容：皇帝与大臣、牛李党争、宦官、世家、方镇、地方管理与监察；文学家诗人；土地、赋役、流民、盐商与经济政策；边患起义及并行政权、族群交往；交通疆域；科技、服饰、礼俗、饮食、酒曲、酒茶政策。晚唐至元应按具体时期处理多政权并行与融合，避免将后世身份直接投射到古人。

## 引用与发布

- 实质性史实使用 Markdown 脚注，脚注内提供完整文字出处与 `[查本机原文](hanji://J18?q=检索词)`。链接不是引文正文的替代。
- 相对文档链接只能落在 `docs/` 内；阅读正文不要链接驱动源码、虚拟环境或本机绝对路径。证据可保存在 `docs/` 内的附件目录，或以文字记录诊断文件位置，不伪造可点击阅读入口。
- 图表、现代地名对应及经纬度说明来源和不确定性。古今同名不代表同地，政区存在时间必须核实。
- 完成后运行 `python makeDocs/validate_docs.py`。禁止为让校验通过而删除待考、虚报已核或创建无内容占位文章。
- 使用`templates/背景综述.md`、`templates/专题研究成果.md`、`templates/资料条目.md`、`templates/文化制度专题.md`与`templates/出处验证记录.md`，只输出实际完成的核验状态。工作未完须明确列出剩余事项。

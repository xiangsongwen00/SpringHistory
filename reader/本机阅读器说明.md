# 史地阅读室：本机阅读器与汉籍出处连接

位置：`E:\历史地理古籍整理\reader`。SpringHistory基于用户指定的 [xiangsongwen00/0-readmd](https://github.com/xiangsongwen00/0-readmd) 源码扩展；保留上游阅读引擎和原有演示入口，新增独立 `local.html`。研究稿只从根目录`docs`读取，原始书库、字体、正文导出和数据库凭据保留本机。

## 新版原文查询（2026-10-23）

双击项目根目录“启动史地阅读室.cmd”，访问 **http://127.0.0.1:18865**。启动器会尝试启动18866原文API，连接用户已配置的PostgreSQL；不会启动、创建或迁移数据库。数据库不可连接时，文稿仍可阅读，原文查询会显示连接提示。

顶部“原文查询”支持按书检索、分页、浏览篇章及读取整章。脚注“查本机原文”打开出处卡后，点击“读取数据库原文”，定位真实章ID并高亮检索词。原文中未解决的私用码仍保留；可切换已核编码映射阅读视图，并展开特殊字记录、下载图片或对象原始资源。显示`decoded_unverified`表示尚未完成原版逐字校勘。

原文请求通过阅读服务的固定只读`/api/text/`代理转发到127.0.0.1:18866，浏览器不直连数据库，也不接收数据库凭据。代理只允许规定的书目、篇章、检索、字符和资源接口；不接受任意URL或SQL。日常检索不依赖旧程序窗口。需要查看旧版显示时，出处卡仍保留旧系统按钮。

案例首页现有宣宗、懿宗和僖宗三个案例，分期、年份和文档清单由`docs/cases.json`提供。新增或修改研究稿后刷新页面，无需重新构建；修改前端代码需运行`npm run build:reader`。

## 打开阅读器

本机已安装依赖并构建。服务运行时，访问 **http://127.0.0.1:18865**。

下次启动可在 PowerShell 执行：

```powershell
& 'E:\历史地理古籍整理\reader\启动阅读系统.ps1'
```

如果本机策略不允许运行脚本，不必修改执行策略，可直接在终端执行：

```powershell
Set-Location -LiteralPath 'E:\历史地理古籍整理\reader'
.venv\Scripts\python.exe local_service.py
```

然后用浏览器访问上述本机地址。前台服务可用 Ctrl+C 停止。18865只绑定127.0.0.1；此前试用8765时Windows返回端口访问错误，故改用18865。

重新安装或修改页面代码后：执行“安装阅读系统.ps1”，或依次创建虚拟环境、安装 `requirements-reader.txt`、`npm ci --ignore-scripts`、`npm run build:reader`。Markdown内容每次打开页面时从现有工作区读取；新增脚注或修改文稿通常不必重新构建。

## 脚注与出处

入口文档已有可试读脚注。推荐的新写法：

```markdown
大中三年，收复地区另有垦田与免税措施。[^土地]

[^土地]: 《旧唐书》卷十八下，大中三年八月制。[查本机原文](hanji://J18?q=五年内不加税赋)
```

1. 点击脚注号跳到注释，再点“查本机原文”。
2. 出处卡显示书名、在本机解析到的卷章标题、书库编号及检索词。
3. “读取数据库原文”直接打开完整章节、来源信息及缺字和资源记录。“旧系统自动定位”另启专用汉籍窗口，按书名定位并勾选，调用“打开”按钮，确认主窗口最大化，再按卷章标题双击目录、输入检索词并查目标卷结果。
4. 自动操作遇到目录、输入框或结果不唯一会停止。可以改用“仅启动书库”，按卡片书名与章节手动操作。
5. 核对正文、命中及上下文后，才能在研究材料中另行记录为“已与本机版本校勘”。系统不会自动把查询发送成功当作校勘完成。

旧稿中的J18、X54、T248等代号已经自动增加点击入口；已登记的维基文库卷链接仍保留，旁边添加“查本机”。没有登记的外部链接不伪造本机定位。新增卷次在 `sources.json` 登记书名、卷次、说明和默认检索词。

本机帮助文件 `jiansuo.htm` 说明可在查询条输入后按回车，支持与、或、同句等条件；`ziji.htm` 说明正文采用简体、GBK字集。第一次试验宜使用短的简体原文。当前不自动进行繁简转换，以免改变专名和异文。

## 实机验收建议

在入口页选择“三州七关”脚注，检索“五年内不加税赋”，依次观察：是否启动正确程序，是否只选《旧唐书》，目录是否选中“旧唐书卷一八下　本纪第一八下”，查询结果是否打开同一卷，正文是否命中该句。记录停在哪一步和提示文字，再据此调整控件适配。当前驱动按控件和标题查找，不使用你截图中的固定坐标。

### 先前排查记录

本节保留此前失败与尝试的过程；“尚待实测”等表述对应当时状态。当前结论以文末及《自动定位实机验收》为准。

用户首次实测停在“未能确认书目勾选”。原实现使用 `pywinauto` 的 Win32 控件树和 `click(where='check')`，随后立即调用 `is_checked()`；错误只证明该判断没有读到勾选，不能证明目标节点不存在，也不能确定唯一根因。

修正版改用控件命中测试定位复选框后执行 `click_input`，等待最多3秒，并读取选择窗口下方的列表内容及树节点状态。若“已选文献名”中已出现目标书，则不再切换复选框；若仍不能确认，只点击一次便停止，避免重复点击导致反选。选书现场保存在 `reader/diagnostics/selection-latest.json`，包括目标文字、树状态、状态图索引、已选列表和控件类名；保存在本机，不通过网页公开。

新增4项回归测试覆盖“自定义勾选状态但已选列表正确”“列表延迟更新”“失败不重复点击”和相似书名区分；连同原有测试共13项Python测试通过。修正尚待再次实机验证。原服务日志另出现32位程序与64位Python的兼容性警告，这是待排查因素，尚无证据表明它就是本次失败原因。

第二次实测：目标为“资治通鉴[宋·司马光]”，复选框点击前后树状态由4096变为4098，仅增加选中标志；状态图索引仍为1，下方列表为空。改按原系统 `xuanze.htm` 明确支持的方式点击书名文字中心，保留原有结果验证，不再使用复选框命中区域的边缘像素。失败时额外保存 `selection-latest.png` 选择窗口截图。这次改动也仍需实机验证，尚未确定原点击失败的唯一根因。

第三次实测及用户纠正：点击书名仍只高亮；用户确认必须点方框后再打开。现已撤回点书名方案，改用目标进程位数对应的 `TVHITTESTINFO` 结构，扫描目标行的 `TVHT_ONITEMSTATEICON` 区域并核对节点句柄，点击方框内部中心；没有找到唯一方框则停止，不回退点击书名。诊断新增 `checkboxHit`（中心、区域边界、节点句柄及目标进程位数）。截图此前因缺少Pillow返回空图像，已补齐依赖并增加空值检查。Python回归测试共15项通过；新版实际勾选效果仍待确认。

## 文件与边界

| 文件 | 作用 |
|---|---|
| `local_service.py` | 本机HTTP服务、文稿读取、出处解析、固定接口 |
| `hanji_catalog.py` | 只读解析本机书目与篇章标题 |
| `hanji_driver.py` | 试验性Windows自动定位适配器，只在用户点击打开按钮后执行 |
| `sources.json` | 允许打开的出处清单，不接受任意命令或EXE路径 |
| `src/local-reader.js` | 脚注、出处卡、文档链接、本机书目 |
| `check_coverage.py` | 生成书目收录核查报告 |
| `test/test_bridge.py`、`test/citations.test.js` | 卷次、来源、API边界与链接测试 |

无正文批量导出，无修改汉籍数据库，无注册自定义系统协议，无修改注册表或执行策略。`hanji://`只由本阅读页捕获；在其他Markdown软件直接点击，未必能打开。服务不接受任意程序路径，打开操作要求本机同源请求和会话标记；未向局域网发布。

## EndSplash监听

按用户要求，本机阅读服务运行期间，每100毫秒检查一次进程，只终止完整路径为 `E:\汉籍全文检索系统\EndSplash.exe` 的进程，不按名称批量关闭其他目录的同名程序。关闭浏览器页面不会停止服务；停止Python阅读服务会同时停止监听。没有安装开机启动项。

已实测直接启动该程序约78毫秒后被关闭，也实测了正常退出汉籍程序触发的EndSplash被关闭。事件记录在 `diagnostics/endsplash-events.jsonl`；运行状态可在 `/api/bootstrap` 的 `endSplashGuard` 字段查看。
